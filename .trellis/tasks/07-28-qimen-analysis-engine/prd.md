# 奇门遁甲规则分析引擎

## Goal

在已经校验并冻结的时家转盘奇门盘面之上，交付一个可审计、可复算、可版本化的本地分析引擎：程序先生成结构化事实，再按显式优先级和首行命中的裁决表给出“可成、难成、待条件、趋势不明”四值结论，最后只从已命中的事实和未决条件生成应期候选。用户、历史详情页和后续 AI formatter 都能追溯每项输出所依据的盘面字段、规则版本、来源和冲突处理过程。

## Hard Dependency

- 本任务对 `07-28-qimen-pan-engine` 存在硬依赖。只有该子任务已完成质量门并归档、`QimenResult` schema、九宫字段、稳定 enum ID、JSON 往返合同和来源化黄金盘均已冻结后，才允许启动本任务实施。
- 分析引擎只能只读消费排盘子任务产出的 `QimenResult` 和黄金 fixture；不得调用时间、定局、地盘、天盘、值符值使、八门、八神或暗干排布服务重新计算或修正盘面。
- 若排盘模型或黄金盘在本任务启动前发生实质变化，必须先回到本任务规划文档重新对齐输入合同并再次评审，不能在分析层做兼容性猜测。

## Background

- 父任务已锁定“事实层 -> 裁决层 -> 应期候选层”的分析路径，并要求分析报告运行时派生、不落库。
- 现有六爻和大六壬分析引擎提供了纯静态 analyzer、四值裁决、首行命中决策表和共享 `Polarity` / `Verdict*` 模型的先例，但现有系统的标签没有完整的稳定规则 ID、来源引用、冲突记录和全链路 trace，奇门不能照搬其不足。
- 奇门规则存在流派分歧。古籍或现代资料没有给出唯一的综合评分公式，因此本任务采用来源化的确定性规则表和保守裁决，不把标签数量、主观权重或 AI 推理当作程序结论。

## Requirements

### R1 只读输入与完整性门禁

- 唯一入口为 `QimenAnalyzer.analyze(QimenResult, {ruleSetVersion})` 或等价的纯函数合同。
- 入口先验证受支持的排盘 schema、九宫唯一完整性以及分析所需字段是否存在；验证只检查现成事实，不重新排盘。
- 不受支持或不完整的历史输入返回带明确兼容状态、稳定错误码和 `QMV1-D00`“趋势不明”解释的诊断报告；禁止静默补值、改宫、换局或降级为另一套规则。

### R2 版本化事实层

- v1 事实规则至少覆盖：九星旺衰、八门旺衰、门迫、六仪击刑、奇仪入墓、空亡、驿马、伏吟、反吟、五不遇时、十干克应、三奇吉格、九遁，以及规则目录中锁定的常见凶格。
- 每个事实必须带稳定 `ruleId`、规则集版本、分类、作用角色、关联宫位/焦点、自然语言理由、直接读取的盘面字段引用和一个或多个来源引用。
- 中五寄宫、天禽随芮、寄宫干/星等事实必须沿用 `QimenResult` 的显式字段；主宫事实和寄宫事实分别记录，不能覆盖或合并后丢失原盘信息。
- 事实输出顺序固定且可复现；同一结果和同一规则版本在不同设备、时区和运行时间下必须产生字节级等价的规范化 JSON。

### R3 来源、分歧与证据治理

- 建立单一规则目录和单一来源目录。规则来源必须记录稳定 source ID、资料性质、书名/版本或 URL+revision、章节目页/定位、访问日期、规则摘义和项目裁定说明。
- 古籍规则、现代整理、外部实现交叉校验和“本项目约定（奇门分析 v1）”必须明确区分；外部开源实现不能单独作为断语或裁决结论的权威来源。
- 有分歧的规则必须记录备选口径、采用口径和采用理由；无法可靠裁定的规则不得进入 v1 的决定性裁决，只能作为中性背景或明确排除。
- 已发布规则集不可原地改义。规则公式、来源裁定、冲突优先级或决策表行为发生变化时必须创建新规则版本，并保留旧版本供黄金测试和审计复算。

### R4 问事焦点

- 基础焦点固定为日干代表求测者、时干代表所问之事；再按 `QimenQuestionCategory` 从盘面选择类别指标，形成有角色、有来源的焦点集合。
- v1 必须覆盖 `general`、`career`、`wealth`、`relationship`、`health`、`study`、`travel`、`litigation` 八类；类别映射属于项目裁定时必须显式标为“本项目约定（奇门分析 v1）”。
- 焦点解析只定位 `QimenResult` 中已经排好的干、星、门、神和宫位，不得另算其落宫；找不到唯一焦点时必须进入可解释的保守分支。

### R5 有序裁决与冲突处理

- 裁决层只消费事实层和焦点层输出，不得再次从原始时间或干支重算事实。
- 使用有稳定行 ID 的自上而下决策表，首行命中且只命中一行；输出限定为“可成、难成、待条件、趋势不明”。
- 冲突顺序必须显式：输入完整性、焦点特异性、规则冲突层级、成对解救/抑制规则、同层未决冲突。被压制的事实仍保留在 trace 中并注明胜出规则和理由。
- 条件可解除的空、墓、迫、刑或迟滞状态转为 `VerdictCondition`，不直接累计为凶；没有明文冲突规则的吉凶并见返回“趋势不明”或“待条件”，不以数量多数决。
- 禁止百分比、置信度百分数、星级、加权吉凶分、正负分相加、标签计数阈值和任何换皮评分。

### R6 应期候选层

- 应期只能从裁决条件、焦点事实和已命中的来源化应期规则生成；不得反向改变事实或裁决。
- 候选必须包含稳定规则 ID、触发类型、日/月/年尺度、干支/节气等结构化触发值、理由、关联 fact/condition ID、来源和确定性排序规则。
- 相同触发键按显式规则去重并合并证据，不能按分数排序；应期措辞必须说明它只是条件成熟或状态解除的观察窗口，不保证事情发生或结论转吉。

### R7 报告、序列化与历史兼容

- `QimenAnalysisReport` 包含分析 schema 版本、规则集版本、输入排盘 schema、输入结果 ID、分析状态、焦点、事实、冲突记录、命中的裁决行、四值结论、条件、应期和完整 trace。
- 报告提供稳定 ID 的 JSON 编解码并通过真实 `jsonEncode` / `jsonDecode` 深比较，用于黄金快照、调试和后续 AI 结构化投影；不得依赖 enum `name`。
- 分析报告及标签不写入 `QimenResult`、Drift 或 SecureStorage。历史记录重开时先由排盘子任务反序列化原始盘面，再用当前规则版本重算；规则升级允许旧盘获得新分析而无需数据库迁移。
- 历史兼容测试必须证明：仅含排盘 schema v1 的记录可重开并得到确定性报告，结果 JSON 不新增 `analysis` 字段；遇到未来/不支持的排盘 schema 时行为明确且不崩溃。

### R8 AI 消费边界

- 本任务只提供由程序生成的结构化分析投影，不调用 AI、不解析 AI 输出，也不允许 AI 回写事实、裁决或应期。
- 投影必须包含程序盘面引用、规则版本、事实、裁决和应期，并携带“程序为唯一排盘与规则计算方；AI 不得重排、重算或静默替换程序结论”的机器可读策略字段。
- 产品集成子任务的 formatter 必须消费该投影，而不是从展示文案、原始时间或九宫字符串自行推导分析。

### R9 文档与质量

- 新增 `.trellis/spec/domain/qimen-analysis-engine.md`，记录规则目录、来源政策、冲突表、决策表、应期合同、版本升级和历史兼容约定。
- 所有领域服务为纯静态或不可变纯函数，不访问 UI、Provider、仓储、网络、系统时钟或当前时区。
- 规则、来源、fixture、测试和文档之间使用稳定 ID 关联，并通过元测试防止遗漏或覆盖率门槛静默下降。

## Acceptance Criteria

- [ ] A1：`07-28-qimen-pan-engine` 已完成并归档，实施记录中固定其提交、`QimenResult.schemaVersion` 和复用的黄金 fixture；依赖未满足时本任务不得启动。
- [ ] A2：静态依赖检查和代码审查证明 analysis 目录不导入或调用任何排盘阶段 service；输入缺失/损坏/不支持 schema 均有确定性测试。
- [ ] A3：v1 规则目录覆盖 R2 全部规则族；每个 rule ID 至少有一项来源、一个正例和一个反例，目录元测试拒绝重复 ID、空来源、未知来源和未覆盖规则。
- [ ] A4：八类问事焦点均有表驱动测试，日干/时干基础焦点不可被类别指标替换，寄宫和多重候选的裁定可追溯。
- [ ] A5：每条事实都能追溯到输入字段、规则版本、来源和宫位；命中、未命中、未适用及冲突压制的 trace 顺序稳定。
- [ ] A6：裁决表每一行和每项冲突策略至少有一个独立命中测试，且断言唯一命中行 ID、四值趋势、条件、因素顺序和压制理由。
- [ ] A7：代码和序列化模型中不存在百分比、星级、加权 score/rating 或标签计数裁决；混合证据测试证明增加无关标签不会改变命中行。
- [ ] A8：每个应期规则至少有正反例；候选仅来自已命中事实/条件，按结构化触发键去重，保留来源链，并明确“不保证成败”。
- [ ] A9：至少 12 个端到端来源化黄金断例来自不少于两个独立出版/公开资料来源，覆盖阴阳遁、四种裁决趋势和主要规则族；全部八类问事、所有裁决行和冲突路径可由来源例加明确标注的章法/边界例共同覆盖。
- [ ] A10：黄金 fixture 元数据包含来源性质、版本/页码或 URL+revision、访问日期、人工裁定、输入 pan fixture、期望 rule IDs、裁决行、条件、应期和 coverage tags；单一外部软件快照不能成为唯一权威。
- [ ] A11：报告经真实 JSON wire round-trip 深比较一致，所有 enum 和规则引用使用稳定 ID；相同输入与规则版本重复运行输出一致。
- [ ] A12：历史排盘 JSON 不持久化 analysis，仓储重开后可重算同版本报告；当前规则版本切换通过显式版本入口完成，旧版本黄金快照仍可复算。
- [ ] A13：结构化 AI 投影只包含程序产出的盘面引用、事实、裁决和应期，并通过合同测试禁止出现要求 AI 重排或自行裁决的字段/指令。
- [ ] A14：目标测试、`flutter analyze` 和全量 `flutter test` 通过，现有六爻、大六壬共享分析模型与行为无回归。

## Out of Scope

- 时间归一化、定局、九宫排布或修正排盘黄金盘；由 `07-28-qimen-pan-engine` 负责。
- 奇门起局页、九宫结果 UI、历史界面、AI formatter、提示词和系统注册；由 `07-28-qimen-product-integration` 负责。
- 飞盘、阴盘、年家、月家、日家和父任务未锁定的全古籍断语库。
- 用机器学习、LLM 或用户反馈自动调整规则权重。
- 把应期候选换算为保证发生的具体公历日期；v1 只提供来源化的结构化触发窗口。

## Constraints

- 排盘事实是唯一输入真相；分析层不能以任何理由重排或“纠错”。
- 规则来源强弱用于审计和准入，不转换成数值置信度或吉凶分。
- 对无法由来源和黄金案例锁定的分歧，宁可输出“趋势不明”并保留证据，也不制造确定结论。
- 本任务完成前不得进入产品入口；产品集成必须继续依赖本任务的冻结报告合同。
