# 大六壬完整性与古籍对照审校

## Goal

系统核查项目现有大六壬排盘、断课分析及其用户呈现的完善程度，逐项与可核验的传统文献规则对照；修复已有错误，补齐影响正确性或实用性的缺项，并以出处、课例和自动化测试形成可回归的实现依据。

## Background And Confirmed Facts

- 当前实现已经覆盖天地盘、四课、九宗门三传、天将、神煞、课格、干支主客、三传分析、综合裁决、应期、AI 格式化及结果页展示。
- 现有大六壬代码主要位于 `lib/domain/services/daliuren/`、`lib/divination_systems/daliuren/` 和 `lib/ai/output/formatters/daliuren_formatter.dart`，并已有相应 unit/widget tests。
- 2026-07-27 已完成九宗门三传修复、断课分析引擎和分析 UI 三组任务；本任务必须复核并复用这些成果，不能把“已经实现”直接等同于“已经有古籍依据且实现正确”。
- 项目规范已经锁定部分排盘口径：寄宫采用六壬寄宫而非禄位，四课方向语义明确，三传按九宗门取法，并要求黄金课例验证。
- 本任务已拆成 10 个路线分组、17 个实施单元（C00-C16）；父任务负责完整性矩阵、证据等级、跨子任务验收和集成复核，不直接吸收子任务遗漏的产品实现。
- 当前大六壬定向测试基线为 100/100 通过；测试集中在九宗门、分析层、formatter 和分析 UI，月将、天地盘、十二天将、神煞缺少独立服务级课例，因此“测试全绿”不能代表古法正确。
- 月将公历时间入口先调用只比较年月日的 `lunar.getCurrentQi()`，导致中气当日实际交节时刻之前提前换将；该错误会整体旋转天地盘并连锁改变四课、三传、天将和分析。
- `ShenShaService` 注释声称覆盖“30+种”，当前固定产出 15 种，且 `riGan`、`shiZhi` 入参未参与计算；天德/月德还可能把天干值写入仅允许地支语义的 `ShenSha.diZhi`，会污染 UI、AI 输出及“神煞命中三传”分析。
- 神煞中的 4 个中性项已被计算并可能被分析层消费，但结果页和结构化 formatter 仅输出吉神、凶神，造成 UI、AI 原始事实与分析标签不一致。
- 十二天将当前把昼夜直接等同于顺逆；夜课同时反转神将表和地支步进，两个反转互相抵消，实际方向恒同。配置模型把映射声明为地盘键，四课/三传却以天盘支查询，圆盘又按地盘支查询，属于已确认的坐标契约错误；具体贵人表和顺逆法须由证据子任务按已选主底本核页冻结。
- 与已定位的《六壬大全》卷一起例转录相比，当前月德、天医、丧门、吊客至少存在公式或起例维度错误；日德、日禄、三奇等未实现。其余神煞须回到影印页逐项核验，不能按现有快照测试认定正确。
- `ChuanAnalysisService` 把“末传与日干寄宫六合”直接并入“传归生身”，且该分支先于末传克日干判断；因此某些实际克身的末传会被标吉，并可能触发裁决表“可成”，属于已确认的结论翻转风险。
- `birthYear` 当前只进入 `DaLiuRenPanParams`，没有本命/行年计算；`Chuan.tianGan`、`isWangXiang`、`relationToRiGan` 也未赋值，结果页所谓“遁干”仅显示旬首与空亡。现有 UI/文档对这些能力的表述超过实际实现。
- 手动四柱模式允许月将“自动”，但自动月将取自操作时的公历 `castTime`，并非用户输入四柱对应时刻；四柱又只逐柱验证六十甲子合法性，未验证年月、日时之间的干支联动，可能接受不存在的组合。
- AI `coreData.overview` 当前已分别输出 `yueJiang` 和 `yueJian`，但缺少完整 schema、版本、证据和全事实断言；本任务将该历史风险锁定为精确 schema 回归，而不重复修复已不存在的重复键。
- “初末传俱空”裁决把两个条件标为 `hasRescue=false`（UI 显示“无解”），应期服务却仍为同一条件生成“值日填实”窗口，UI 与 AI 会同时输出互相矛盾的判断。
- `DaLiuRenViewModel.castByManual()` 默认选择手动月将模式却不提供手动月将，调用公开便捷方法的默认参数组合会被系统校验拒绝。
- 分析层以中文展示词作为裁决和应期的执行键，没有稳定 `ruleId`、证据等级或规则版本；历史盘也没有排盘引擎版本，旧错误盘会被当前分析器当成现行规则事实继续解释。
- `docs/architecture/divination-systems/daliuren.md` 仍保留“三传占位、当前固定样例错盘”等修复前描述，已经与 2026-07-27 后的实现和 domain spec 冲突。
- 九宗门主体已覆盖九法并基本符合当前 spec，但现有 13 例均为内部位移盘；涉害多级平局、遥克多候选、昴星刚日、别责刚日、八专阴日/有克、伏吟有克等分支缺测。现有 spec 还把反吟无克写成四日，而《六壬大全》起例列为丁己辛之丑未六日；代码使用通用判断，尚未受该文档错误限制。
- 仓库没有《大六壬指南》《六壬大全》等原典文件，现有引用多只到书名或“课体章”，没有版本、卷页和原文定位；公开馆藏可取得《大六壬指南》影印件及《钦定四库全书·六壬大全》十二卷影印件，但 OCR 质量不足，引用需回到影印页核验。
- 用户已选择分层单一基线：《钦定四库全书·六壬大全》十二卷作为起例、神将、神煞、六十四课经和毕法赋的主底本；《大六壬指南》作为断课主依据；《大六壬断案》《六壬存验》用于外部课例验证；《壬归》《六壬粹言》《大六壬探原》等仅用于补缺和登记异文。
- 用户已选择保守的历史盘升级策略：保留旧记录并显示排盘引擎/分析规则版本；只有原始输入足以可靠重放时才允许生成关联的新版本记录，禁止静默覆盖原记录。缺少原始报数或随机种子的旧记录只能标注旧口径，不伪装成可原样重排。

## Requirements

- 本任务采用一次性完整交付范围：除修复现有核心错误外，同一父任务内补齐 64 课经、毕法百法、类神/占类、本命与行年、三传遁干与旺相、完整神煞、传统断课与应期等主要知识体系，不把这些能力延期为任务外后续项。
- 可按独立可验收能力拆成子任务并分批实施，但父任务只有在全部子任务、跨层集成和最终古籍审校通过后才完成。
- 建立大六壬功能与规则清单，标记已实现、部分实现、未实现、实现存疑和明确错误。
- 对每个需要修改或补充的规则记录：规则名称、适用条件、优先级、文献依据、版本/流派差异、当前实现位置、预期行为和验证课例。
- 优先处理会改变排盘基础结果的错误，其次处理会改变断课结论的错误，再处理解释深度、展示和可维护性问题。
- 对存在流派差异的规则保留可追溯口径，不把单一说法伪装成唯一古法；若产品需要选择默认口径，必须在规划中明确。
- 规则冲突以分层主底本优先，不把多个传本静默拼接；只对证据充分、会实质改变盘面且确有用户价值的重要流派差异提供显式配置，其余差异在证据登记和结果说明中展示。
- 修复和新增规则必须通过独立预期值或传统课例验证，避免仅以当前实现生成的结果反向断言其正确。
- 建立规则证据登记表，至少记录底本题名、版本/馆藏标识、卷次或影印页、原文摘录、解释、对应代码和验证课例；OCR 仅用于检索定位，不作为最终引文。
- 优先复核当前缺乏独立测试的月将、天地盘、贵人/十二天将和神煞链路，并修正字段语义跨层错位。
- 月将边界必须按精确交节时刻判定，并覆盖交节前一秒、交节时刻和交节后一秒。
- 十二天将必须分别建模“昼夜所选贵人支”“贵人所临地盘宫”“实际顺逆”“天盘支乘将”和“地盘宫落将”，禁止复用一个含混 map。
- 神煞必须先建立有类型的位置与起例模型（年/月/季/日干/日支/时），再按核定底本修表和扩充；未验证项不得输出确定性古法标签。
- 古籍事实、项目启发式和纯展示文案必须使用稳定标识与显式证据等级；展示词修改不得静默改变裁决行为。
- 同一事实或条件在领域报告、UI、AI 人类可读文本和机器可读 `coreData` 中必须保持一致，不能同时出现“无解”和“可填实”等互斥结论。
- 为历史结果实现可观察的版本策略：缺少版本字段的记录识别为旧口径并明确提示；新记录保存排盘引擎版本、分析规则版本所需的来源信息和可重放输入快照；仅在原始输入充分时提供可选重排，重排生成带来源关联的新记录，不能无标识地套用新分析或覆盖原记录。
- 保持既有历史记录、模型序列化、AI 输出和 UI 消费契约兼容，除非规划明确列出迁移方案。
- 最终给出可复核的完善程度报告，说明已修复项、仍缺项、流派争议项和后续优先级。

## Acceptance Criteria

- [ ] 形成覆盖排盘基础、四课三传、天将神煞、课格/断课、应期、AI 输出和 UI 的完整性矩阵，并能追到具体代码与测试。
- [ ] 每个纳入实现的修复或补充项都有明确文献/课例依据和至少一个可失败的回归测试。
- [ ] 每条“古籍规则”引用可定位到具体底本卷页或影印页；每条“项目约定”被显式标注，二者不混用。
- [ ] 基础排盘与三传的高风险分支具有成组边界课例，结果不依赖测试内复制生产算法。
- [ ] 月将、天地盘、贵人/十二天将、四课乘将和神煞分别具备独立服务级测试，并至少有一个完整盘贯通验证。
- [ ] 月将中气交节边界不提前换将；十二天将至少覆盖昼/夜贵分别落顺区与逆区的四类交叉盘。
- [ ] 九宗门每个阴阳分支和多级决胜路径有回归例，反吟无克六日与最终采用底本一致。
- [ ] 分析层只消费可验证的排盘事实，定性和裁决规则的优先级、互斥关系及降级行为有测试覆盖。
- [ ] 用户可见的规则名称、解释、AI 数据和结果页展示与修正后的领域模型一致。
- [ ] AI 结构化输出分别提供月建与月将且无重复覆盖；分析事实含稳定规则标识、证据等级和版本。
- [ ] 裁决条件、应期、UI 与 AI 对“有解/无解”的语义一致，并有贯穿 analyzer、widget、formatter 的冲突回归测试。
- [ ] 缺少版本字段的历史盘能正常读取并显示“旧口径/版本未知”提示；新盘带明确版本和可重放输入快照；重排只新建关联记录且原记录保持不变，不可可靠重放的旧盘不显示误导性重排能力。
- [ ] 证据目录恰有 64 个课经规则和 100 个毕法规则；每条都有稳定 ID、影印页、采用解释、可执行 typed 条件和独立正例，易误命中项另有反例/边界例。
- [ ] “完整神煞”已冻结为有限清单；清单每项要么实现并验证，要么明确排除并说明理由，数量来自目录而不是当前 15 项或“30+”注释。
- [ ] 有限占类 taxonomy 全覆盖；类神选择可解释、可覆盖、可降级，相同盘面在不同占类下只改变分析上下文而不改变基础盘。
- [ ] 本命/行年所需的性别、年龄、出生年柱/日期和岁首口径按核定底本实现；不再存在可填写但不生效的 `birthYear`。
- [ ] 三传遁干、旺相休囚死和对日干关系全部有值或显式 unknown，日旬/时旬模式均有独立测试。
- [ ] 至少两张页级核定的外部完整盘贯穿起课、月将、天地盘、天将、四课三传、神煞/经典规则、断课、应期、UI、AI 与保存恢复；预期不由生产算法生成。
- [ ] C00-C16 全部独立验收并归档，父任务能力矩阵没有未归属或以“后续”规避的一次性交付项。
- [ ] 相关静态检查、单元测试和组件测试通过，且不存在因修复产生的未说明兼容性回归。
- [ ] 审校报告区分“已验证正确”“已修复”“未实现”“有争议/暂缓”，并给出剩余风险。

## Out Of Scope

- 未注明版本、无法追溯原文或仅见于现代转载的规则，不作为“古法已实现”的依据。
- 不保证占断结果具有现实预测效力；验收目标是软件实现与所选文献口径、课例和数据契约一致。
- 不改动大六壬以外的术数模块，跨系统共享模型兼容所需的最小调整除外。
- 古籍扫描件本体不纳入仓库，只保存馆藏标识、卷页、必要短引文和推演记录。
- 不把所有传本差异都做成运行时配置；未选为默认的非关键异文只保留可追溯记录。
- 不对缺少原始报数、随机种子或其他必要输入的旧记录推断、补造原始起课输入；允许继续查看旧盘，但必须保留版本警示。
