# 大六壬古籍证据库与外部课例

## Goal

在任何大六壬规则扩展或改写前，建立可机审、可回到影印页人工复核的古籍证据库，冻结本父任务的有限规则清单、采用口径、异文和独立课例，使后续实现不再凭书名级引用、OCR 或现有代码自证。

## Background

- 当前仓库没有古籍原典或页级规则登记；现有引用多只到书名或章节。
- 已确认可访问《大六壬指南》及四库本《六壬大全》十二卷影印件；OCR 质量不足，只可定位。
- 《大六壬断案》尚未登记可核版本；《六壬存验》目前只有固定转录定位，均需在本任务中补影印底本或明确证据上限。
- 本任务是其余 16 个实施单元的硬前置，不修改产品算法。

## Requirements

- 建立 source registry，记录题名、作者/版本信息、馆藏、identifier、卷册、文件、影印页码体系、访问日期和适用规则层。
- 每条规则记录稳定候选 ID、规则族、适用条件、优先级、底本卷页/影印叶、必要短引、解释、异文、采用口径、证据等级、目标代码域和 fixture ID。
- OCR/转录条目必须标记为 locator-only；没有回到影印页的规则不得达到 A/B 级或进入确定性实现清单。
- 按规则族分文件冻结有限清单：历法/月将、天地盘、四课、贵人天将、九宗门、旬空遁干、旺相、神煞、本命行年、占类类神、64 课经、100 毕法、传统断课、传统应期。
- 六十四课经目录恰好 64 个 ID，毕法赋目录恰好 100 个 ID；完整神煞和占类 taxonomy 必须成为可数清单并记录明确排除项。
- 登记《大六壬断案》《六壬存验》的外部完整课例，保存原始时间/四柱、问题、人物上下文、盘面与断语定位、可确定的预期事实及未决项；不调用生产代码生成预期。
- 对主底本冲突采用分层优先规则；只有证据充分且会实质改变盘面的重要流派差异才标记为可配置候选。
- 提供结构化 schema 和自动校验，检查 ID 唯一、sourceRef/fixtureRef 完整、证据等级合法、页码存在、64/100 数量、孤儿规则和 locator-only 越权。
- 扫描件本体不入库，只保存馆藏标识、页码、必要短引文和推演记录。

## Acceptance Criteria

- [ ] 所有采用底本均有明确版本/馆藏、文件和可复查的影印页定位体系。
- [ ] 每个进入后续实现的规则至少为 B 级，且可从 rule entry 一步追到影印页；C/D 条目不会被标成已验证古法。
- [ ] 自动校验确认 64 课经、100 毕法数量准确、ID 唯一、引用完整且无占位条目。
- [ ] 神煞清单、占类 taxonomy、本命行年输入口径和应期规则清单已经有限化，逐项有采用/排除状态。
- [ ] 贵人表、昼夜边界、落宫顺逆、九宗门重大分歧和反吟无克六日已有明确采用口径。
- [ ] 至少两张可复算的外部完整课例具备页级出处、原始输入和独立预期；不足字段明确 unknown，不能由生产算法补造。
- [ ] validator 对重复 ID、缺页码、悬空引用、错误数量、locator-only 冒充 A/B 和无 fixture 的启用规则均会失败。
- [ ] 形成一份证据覆盖报告，按规则族列出批准、待核、排除和争议，不把待核项算入完成度。

## Out Of Scope

- 不在本任务中修改月将、天将、神煞、三传或分析算法。
- 不把整本 PDF、扫描图或大段原文提交到仓库。
- 不因暂时找不到某底本而用博客、AI 推断或当前测试替代影印证据。
