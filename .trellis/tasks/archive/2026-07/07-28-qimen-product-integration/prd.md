# 奇门遁甲界面与应用集成

## Goal

把已经冻结的奇门排盘与规则分析能力接入万象排盘现有产品骨架，交付从首页入口、自动/手动起局、保存、完整九宫结果、本地裁决与应期、AI 解读，到历史重开、导入导出和按系统清理的完整用户闭环；任何入口展示、持久化恢复和 AI 输出都只消费程序生成的结构化合同，不在界面层重新排盘或改写裁决。

## Hard Dependencies

- 本任务只能在 `07-28-qimen-pan-engine` 与 `07-28-qimen-analysis-engine` 均完成质量门、提交并归档后启动。
- 启动时必须记录两个上游子任务的提交、`QimenResult`/`QimenAnalysisReport` schema、稳定 enum ID、黄金 fixture 和公开消费接口；若交付合同与本规划存在实质差异，先修订规划并重新评审。
- 本任务不得为了适配 UI 修改定局、九宫排布、事实规则、裁决表或应期算法；发现上游缺陷时返回拥有该合同的子任务修复。

## Background

- 仓库已有统一 `DivinationSystem`、`DivinationUIFactory`、Provider/ViewModel、通用 Drift 记录、SecureStorage 占问、历史详情、数据管理和 AI formatter/template 骨架。
- 通用记录通过稳定系统 ID、起局方式 ID 与结果 JSON 保存，因此新增奇门无需数据库 schema migration；但未注册或无法反序列化的系统记录会在读取时被跳过。
- 新增第五个 `DivinationType` 会触发首页、历史、设置、AI 和生成代码中的穷举分支，必须在同一发布门内完整接通，禁止半启用。

## Requirements

### R1 系统入口与发布门

- 使用稳定系统 ID `qimen`，复用 `CastMethod.time` 与 `CastMethod.manual`，并保证 `time` 排在支持方式首位。
- 同时注册 `QimenSystem` 与 `QimenUIFactory`，提供 `QimenSystem` 和 `QimenViewModel` 的依赖注入；缺少任一依赖时不得把系统设为启用。
- 首页显示可辨识的奇门名称、副标题、图标、独立系统色和真实位图背景；首页入口、最近记录和历史卡片的系统名称/颜色一致。
- 全仓所有 `DivinationType` 穷举 switch、硬编码系统列表、枚举数量/ID 测试与生成序列化代码必须一次性补齐。

### R2 起局页完整输入

- 起局页支持自动时间起局与手动校盘，并保存/恢复用户最近一次使用的合法起局方式。
- 两种方式均支持占问文本和八类问事类型；占问文本继续走现有加密存储，不混入结果 JSON。
- 自动起局可选择日期时间、拆补/茅山/置闰、当地民用时间/北京时间/真太阳时、23:00/00:00 换日、寄宫口径与暗干口径。
- 真太阳时模式仅在生效时显示经度输入，并对 `[-180, 180]`、空值和非数字给出就地错误；其他时间模式不提交无效经度。
- 手动校盘必须显式输入合法四柱、节气、阴阳遁、1..9 局和上中下元，并复用问事、寄宫和暗干参数；禁止静默使用调试默认四柱。
- 常用输入保持在首屏主流程，高级口径可展开但当前选值始终可见；提交中防重复点击，校验失败不保存、不导航。

### R3 起局、保存与错误状态

- 所有输入由 `QimenViewModel` 转成上游已经冻结的类型化 payload，系统层仍是最终校验边界。
- 起局成功后先完成记录与加密占问保存，再通过统一 UI registry 进入结果页；保存失败时显示明确错误且不伪装为成功。
- 页面完整呈现 idle、validating/casting、saving、success 和 error 状态；离开页面或异步完成后不得对已销毁 context 调用导航或提示。

### R4 完整结果页与九宫交互

- 结果页固定顺序为：时间/四柱与口径摘要、局数和值符值使、洛书九宫、关键标记、规则裁决、格局/宫位事实、应期、AI。
- 九宫按 `4-9-2 / 3-5-7 / 8-1-6` 稳定 3x3 排列；格子尺寸、边框和核心字段位置不因标签数量、加载状态或点击状态跳动。
- 每宫摘要至少可扫描宫号/方位、地盘与天盘干、九星、八门、八神、暗干、寄宫、空亡/驿马状态；中五原盘事实与寄宫事实分别显示。
- 点击任一宫打开完整详情 sheet，展示全部结构化字段、专业标记及其来源说明；小格中不堆叠长解释文字。
- 时间基准、校正分钟/算法版本、换日、定局法、寄宫和暗干口径在结果页可见，使用户能判断该历史盘采用何种规则。

### R5 本地分析与可审计展示

- 结果页运行时从 `QimenResult` 派生 `QimenAnalysisReport`，展示四值结论、命中裁决行、未决条件、焦点、事实标签、冲突压制理由、来源与应期候选。
- 默认先呈现可扫描的结论与关键证据，完整推理链和来源按需展开；不得用百分比、星级、加权分或标签数量表现吉凶。
- 对不支持的盘面/分析 schema 或无唯一焦点，展示分析报告的诊断状态和“趋势不明”解释，盘面本身仍可查看，页面不得崩溃或静默换规则。
- 应期明确标为观察窗口，不承诺事件一定发生或结论自动转吉。

### R6 历史与数据管理闭环

- `QimenResult` 保存、读取、最近记录、按系统筛选和详情重开完整可用；历史详情的盘面与首次结果深比较一致，分析按明确规则版本重新派生。
- 历史卡片使用系统统一骨架和 `QimenResult.getSummary()`，可从卡片进入注册表构建的奇门结果页。
- 数据管理显示奇门记录数量、总量变化和独立清理操作；清理奇门不影响其他术数。
- 导出包含稳定 `qimen` ID、method ID 和完整结果 JSON；导入后可被注册系统恢复，损坏或未知 schema 记录按现有错误策略报告而不破坏其他记录。

### R7 AI 结构化输出与降级

- 新增并注册 `QimenStructuredFormatter`，只消费 `QimenResult` 与分析子任务提供的 `QimenAnalysisProjection`，不从时间、展示文本或宫位字符串自行推导。
- formatter 输出排盘口径、九宫事实、焦点、命中/压制事实、裁决、条件、应期、来源和规则版本，并携带“程序是唯一计算方，AI 不得重排、重算或覆盖裁决”的约束。
- 提供奇门系统模板、综合分析模板和简要分析模板，补齐 prompt assembler、设置标签、AI 会话标签与所有穷举分支。
- 未配置 AI、formatter 不可用或分析处于兼容诊断状态时，本地盘面与规则分析仍完整可用；AI 入口给出受控提示，不造成页面异常。

### R8 响应式、可访问性与视觉资源

- 九宫盘、表单和详情在窄屏、宽屏和大字体下无横向溢出、文字重叠、不可点击区域或动态尺寸跳变；长术语允许换行或进入详情，不缩放为不可读文字。
- 宫格、标签、按钮和弹层提供可理解的 Semantics；颜色不能作为吉凶、选中或空亡状态的唯一提示。
- 操作控件遵循现有设计系统：方式/模式用分段或下拉选择，布尔项用开关，数值用输入控件，明确命令使用图标加文字；不创建平行导航或卡片嵌套卡片。
- 背景资源必须是项目内可发布的 PNG/JPEG/WebP 位图，来源/生成方式可追溯，并在首页卡片真实渲染；不以手绘 SVG 或纯渐变代替。

### R9 文档与质量

- 补齐 `docs/architecture/divination-systems/qimen.md` 的产品、历史和 AI 合同，更新系统索引、统一接口文档以及受影响的 domain/frontend specs。
- 为 enum/registry、ViewModel、起局表单、结果页、九宫窄屏、详情、历史往返、数据管理、formatter/templates 和 AI 降级建立自动化测试。
- 代码生成、格式化、静态分析、目标测试和全量测试必须通过，现有四个术数的入口、历史、数据管理和 AI 行为无回归。

## Out of Scope

- 修改时间归一化、定局、转盘九宫、事实规则、裁决表或应期算法。
- 飞盘、阴盘、年家、月家、日家奇门界面。
- 自动定位、地图选点、后台位置权限或云同步。
- 独立数据库表、schema migration 或现有历史架构重构。
- 在 UI 或 AI 层扩充未被分析 v1 规则目录锁定的古籍断语。

## Constraints

- 系统、UI、历史、数据管理、AI 与资源必须作为一个发布门；任何一项不完整时 `qimen` 保持未启用。
- 盘面事实来自 `QimenResult`，分析事实来自 `QimenAnalysisReport`；组件和 formatter 只格式化，不复制业务规则。
- 所有外部存储与模板关联使用稳定 ID，禁止依赖 enum `name` 或中文展示名。
- 不覆盖或清理工作区中与本任务无关的现有改动。
