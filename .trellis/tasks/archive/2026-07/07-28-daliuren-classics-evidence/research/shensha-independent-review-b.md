## 复核方法与口径

1. 逐页打开 220 DPI 影印渲染，并回看相邻页，区分逐条起例正文、`逐月神煞` 十二支表和后续 `总钤/德煞`。
2. 本册 `pdfPage == scanLeaf`；没有独立书叶映射，`printedLeaf` 必须保持 `null`。
3. PDF 37-38 只批准条目名和首次页位，不把月序小字直接转写为 executable formula。
4. PDF 39-56 是逐月表。只批准表内名称存在和首次出现页，不批准每月十二支值，也不据同名自动判定与前文规则为同一算法。
5. 简体 `traditionalName` 可作为规范展示名；固定转录的连写、OCR 误字和异体字必须由影印页校正，不能反过来支配影印。

## 与前半复核的交叉结论

前半正式复核推翻了固定转录的一个关键释读，并发现另一个漏项：

- PDF 33 在 `支害` 与 `支仪` 之间的单字题头，影印更支持 `關`，不能直接采用固定转录的 `时煞`。当前 PDF 39 的逐月表 `时煞` 应保持独立条目；`關` 另列 `C/disputed`，等待异本或上下文消歧。
- PDF 36 明见 `天雞、雌虎、地醫酉逆十二`，当前清单漏了 `天鸡`。其目录与原文公式可达 B，但本轮仍不批准 typed 执行。

现有 registry、生成源均未入 Git 历史，仓库内也没有任何 `dlr.rule.shensha.*` 或 `daliuren.shensha.*` 下游引用。因此 C00 应在首次正式冻结前按影印顺序重建 236 条清单：加入 `關`、`天鸡`，同步修正前半题名和首见页，然后一次性重新编号。该次冻结必须记录在研究说明中；从 C01 建立正式 provenance 合同后，规则 ID 才进入“不可无迁移静默改写”的阶段。
