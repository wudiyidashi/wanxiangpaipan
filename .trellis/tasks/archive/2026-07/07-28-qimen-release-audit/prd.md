# 奇门发布纠偏与最终验收

## Goal

在不回滚已审定正确的奇门规则、不改写 Git 历史的前提下，修复产品集成任务的
所有权和验收证据偏差：把首次启用前发生的分析修正建立为可追溯的 v1 发布基线，
补齐自动起局边界、手动非法输入、异步卸载和入口导航等缺失测试，并让归档子任务、
父任务与实际提交历史一致后再发布。

## Requirements

### R1 首次发布基线与版本边界

- 保留 `qimen-shijia-zhuanpan-analysis/v1`，但明确 `8138c6e` 是首次启用前的
  最终 v1 实现基线；`a83647e` 仅为内部禁用候选，不作为用户可选旧版本。
- 将最终 v1 fixture 哈希、首次启用提交和“启用后语义变化必须新增规则版本”写入
  analysis spec；不得放宽已经发布版本不可变的原则。
- 不伪造独立代码提交、不 amend/rebase；用本任务记录混合提交的真实 provenance。

### R2 产品输入与状态机补测

- 自动方式至少覆盖 `-180`、`180` 合法真太阳时 payload、茅山法提交，以及用户
  选择日期和时间后实际 cast 使用所选值。
- 系统边界分别拒绝未知节气、未知阴阳遁、局数 `0/10` 和未知三元。
- widget 在 cast/save 尚未完成时卸载，完成后不得导航、显示 snackbar 或抛异常；
  saving 期间的第二次点击不得产生第二条记录。
- 首页启用奇门卡片后，点击必须经 UI registry 到达 `QimenCastScreen`。
- 结果页分别覆盖无唯一焦点诊断与显式规则版本切换；若现有 v1 只有一个 released
  版本，测试必须锁定 UI 使用 current/显式版本的可替换边界，不伪造不存在版本。

### R3 全量验收映射

- 逐项重新映射产品 PRD A1..A14 和父任务全部 acceptance；实现存在但无精确证据的
  项目必须补测或诚实标为未满足，禁止仅凭测试总数勾选。
- 保留已通过的九宫 320/390/600、横屏、大字、九宫详情、兼容诊断、仓储往返、
  数据管理、AI formatter/template/降级和资源测试，不复制已有覆盖。

### R4 证据修正与归档

- 在已归档产品任务中保留原始 A1 失败事实，并新增关联本纠偏任务的替代验收；
  修正分析提交/fixture 时间线和“tests first”不可证明的说明。
- 父任务只有在本任务质量门通过并归档后才能重新勾选完成。
- 只暂存奇门纠偏白名单；并行大六壬、`tmp/` 和其他用户改动保持未暂存。

## Out Of Scope

- 回滚 `8138c6e` 中来源审计已确认正确的规则修正。
- 为从未启用、未 tag、未推送的内部候选实现维护可选择的错误 v1。
- 新增奇门流派、规则、产品功能、数据库 migration 或改变现有 UI 设计。
- 修改、清理或提交并行大六壬工作。

## Constraints

- 生产代码只在补测暴露真实行为缺陷或为可测试性提供最小稳定入口时修改。
- 分析 report 仍运行时派生、不落库，因此基线纠偏不得引入历史数据迁移。
- 不 amend、不 rebase、不强制暂存归档目录；使用前向提交修复证据。
