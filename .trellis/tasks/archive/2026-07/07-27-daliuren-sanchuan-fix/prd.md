# 九宗门三传正确性修复与黄金课例

## Goal

修复大六壬排盘引擎的正确性缺陷，使九宗门三传取法完整且符合《大六壬指南》/《六壬大全》口径，并以服务级黄金课例锁定回归。

## Background / 已确认缺陷

1. **天干寄宫表错误（最严重）**：`daliuren_constants.dart` 现用禄位体系（乙寄卯、丁己寄午、辛寄酉、癸寄子）。六壬正宗为"甲课寅兮乙课辰，丙戊课巳丁己未，庚课申兮辛课戌，壬课亥兮癸课丑"，四正（子午卯酉）不寄干。旁证：唯有此表能推出古籍八专五日（甲寅、庚申、丁未、己未、癸丑）。乙丁己辛癸日四课全错。
2. **贼克优先序颠倒**：`si_ke_service.dart` / `san_chuan_service.dart` 先取上克下；正宗为"取课先从下贼呼，如无下贼上克初"（下贼上优先）。
3. **伏吟三传全同**：伏吟时天盘为恒等映射，中末传沿天盘链推导导致初中末相同；正宗应走刑传链（自任/自信/自刑处理）。
4. **反吟取用错误**：有克时取了下神（应取上神）且未走比用/涉害裁选；无克未取驿马发用。
5. **涉害为占位实现**：直接取日干寄宫上神，无涉害深度计算与孟/仲/刚柔日决胜。
6. **遥克、昴星、别责、八专未实现**：四课无克时错误落入涉害兜底。
7. **`Ke` 模型注释与 `SiKeService` 赋值语义矛盾**（isZeiKe/isBiYong 方向相反）。

## Requirements

- R1 修正天干寄宫表为六壬口径；禄位如被神煞（日禄等）使用，须拆出独立禄位表，不得混用。
- R2 四课克判定：isZeiKe=下贼上（下克上），isBiYong=上克下，与模型注释一致；两方向独立判定。
- R3 三传九宗门完整实现，判定顺序：伏吟/反吟（天地盘结构）→ 八专日特判 → 贼克（下贼上优先）→ 比用 → 涉害（深度+孟仲+刚柔决胜）→ 遥克（蒿矢先、弹射后，多者取比）→ 昴星（刚仰柔俯）→ 别责（三课备）。规则细节以 design.md 的锁定口径为唯一依据。
- R4 每种课体的 `keTypeExplanation` 说明取用理由（含涉害深度数值、比用取舍等）。
- R5 建立服务级黄金课例测试（design.md 附 13 例，覆盖全部九宗门与优先序/寄宫回归），直接构造天盘+日干支输入，不依赖日期换算。
- R6 现有日期级样例测试（2026-04-18）按修正后引擎重新推演期望值，并逐项人工核对后更新。
- R7 排盘口径沉淀为 `.trellis/spec/domain/daliuren-pan-engine.md`（步骤 3.3 完成）。

## Constraints

- 不迁移历史记录：已存库的旧排盘结果不做数据迁移，仅新排盘走新引擎。
- 不改变 `Ke`/`SiKe`/`SanChuan` 的 JSON 字段结构（序列化兼容）；语义修正只发生在计算侧。
- 派系分歧处按 design.md 锁定口径实现，并在 spec 中标注"存在他派"，不做可配置化（本任务范围外）。
- 不动六爻侧任何文件；工作区遗留的 3 个六爻改动不纳入本任务提交。
