# 六爻裁决层：作用图求值+裁决决策表+趋势输出

## Goal

在现有分析引擎（事实层/状态层/角色层/应期层已完成）之上补齐"裁决层"：
选定用神后，引擎按《增删卜易》口径输出**结构化趋势判断**（成/难成/待条件/趋势不明）
+ **未决条件集** + **可审计推理链**，取代目前仅拼接标签的 `verdictSummary`。

## 背景与约束

- 裁决口径延续 spec 既有决策：一切流派分歧以《增删卜易》为唯一基准。
- 输出形态为"趋势 + 条件"，**不是吉凶分数**；不得按吉凶标签数量加权求和判定成败（spec 既有口径）。
- 裁决结果为派生数据，与 `AnalysisReport` 一样**不落库**（规则升级后旧卦自动获得新裁决）。
- 裁决层消费既有标签（与 `YingQiService` 按 term 消费标签的模式一致），不重算事实层。
- 未选用神时不输出裁决（与现有 verdictSummary 行为一致）。

## Requirements

1. **趋势裁决**：给出四值趋势 `可成 / 难成 / 待条件 / 趋势不明`，附细化语气
   （如"先难后成""成而迟滞"），依据裁决决策表（用神净状态 × 元/忌神动静 × 悬置状态）。
2. **力量分层**：受力评估遵守《增删卜易》作用力层级——日月 > 动爻 > 暗动 > 变爻（仅回头作用本位）；
   静爻不作用。合住/贪生等遮蔽规则沿用既有标签结论（贪合忘生克、冲开解合等）。
3. **悬置状态转条件**：真空、月破、入墓、合住、伏藏、化空/化破/化墓/化绝不直接判凶，
   而是转入未决条件集（待出空/出月/冲开/出伏……），并与既有应期候选衔接
   （条件集中的每个条件应能对应到 ≥1 个应期候选或明确"无解救"）。
4. **推理链可审计**：每条触发的裁决规则记录 {规则名、作用方向、理由、经文出处}，
   供 UI 展开和 AI 提示词使用。
5. **verdictSummary 升级**：摘要文案由裁决结果生成（趋势 + 关键条件 + 应期提示），
   保留"应期候选仅是条件触发窗口"的免责表述。
6. **UI 最小接入**：结果页总览卡展示趋势与条件集（沿用现有 verdictSummary 展示位，
   结构化推理链本期仅保证数据可用，完整 UI 可后续任务再做）。
7. **伏神取用**：裁决基于伏神自身状态 + 飞伏关系（飞来生伏/飞来克伏等），
   不复用飞神标签（spec 既有口径）。

## Acceptance Criteria

- [ ] `LiuYaoAnalyzer.analyze()` 在指定用神时返回结构化 `VerdictJudgment`（趋势/条件集/推理链），未指定用神时为 null。
- [ ] 裁决决策表每条规则 ≥1 正例 + 1 反例单测（沿用 `analysis_fixtures.dart` 夹具）。
- [ ] 黄金断例测试：≥30 个《增删卜易》断例夹具（月日干支 + 卦 + 用神 → 期望趋势），
      按旺衰、空破墓绝、合冲、动变、元忌、飞伏、应期条件组成覆盖矩阵；引擎裁决与期望一致；
      每例注明问事、月日、取用、出处章节及校对本页码，章法推演而非原书实占者必须明确标注“章法校验例”。
- [ ] 悬置状态（旬空/月破/入墓/合住/伏藏）均产出条件而非直接判凶，有单测锁定。
- [ ] 旧行为兼容：未选用神的分析报告与本期改动前完全一致（回归测试）。
- [ ] `flutter analyze` 无新告警；`flutter test` 全绿。
- [ ] spec `liuyao-analysis-engine.md` 口径表补充裁决层规则。

## Out of Scope

- 问事类别 → 用神自动选取（仍由用户点选用神）。
- 象法、外应、神煞参与裁决。
- 推理链的完整 UI 展示与 AI 提示词模板改造（数据就绪即可，另立任务）。
- 标签 term 从字符串重构为枚举（保持与 YingQiService 一致，另行评估）。
