# 奇门遁甲板块（父任务）

## Goal

在万象排盘中交付一个可独立使用的奇门遁甲完整产品闭环：用户可以按明确口径起局、查看和校验完整九宫盘、获得可追溯的本地规则分析与 AI 解读，并通过现有历史记录和数据管理能力长期保存、重开与清理结果。

## Background

- 用户确认范围为“完整产品闭环”，不是只展示基础盘面的 MVP，也不扩展到全流派全层级。
- 仓库目前没有奇门系统、领域模型、排盘服务、UI 或测试，但已有统一术数注册、起局、结果、历史、数据管理和 AI formatter 架构。
- `lunar 1.7.8` 能提供精确节气和干支历法数据，不提供奇门定局与九宫排布；Pub.dev 也没有满足本任务的成熟 Dart 奇门引擎。
- 规则基线与外部实现可信边界见 `research/qimen-rule-baseline.md`，应用影响面见 `research/integration-map.md`。

## Requirements

### R1 时家转盘体系

- 实现时家转盘奇门，支持拆补、茅山、置闰三种定局法；拆补为默认。
- 支持 `time` 自动起局与 `manual` 四柱/阴阳遁/局数/三元校盘录入。
- 茅山法按交节所在时辰起算，每元 60 时辰；置闰法按超神接气动态判定，仅在芒种/大雪满足条件时置闰。

### R2 时间与可复算上下文

- 默认使用设备当地民用时间，可切换北京时间或经度真太阳时。
- 真太阳时同时计算经度差与方程时校正；算法版本、输入值与校正分钟随结果保存。
- 默认子初 `23:00` 换日，可切换民用 `00:00` 换日。
- 保存原始时间、实际排盘时间、时间基准、UTC offset、经度、换日规则、相邻节气时刻与四柱，使历史结果不依赖设备当前环境即可复算。

### R3 完整盘面与分歧口径

- 展示并保存阴阳遁、局数、三元、符头、旬首、值符值使、九宫、地盘/天盘、九星、八门、八神、暗干、空亡、驿马和专业标记。
- 默认中五寄坤二、天禽随天芮；兼容阳遁寄艮八/阴遁寄坤二。
- 八神次序固定为值符、螣蛇、太阴、六合、白虎、玄武、九地、九天，阳顺阴逆。
- 暗干默认值使落宫起时干、阳顺阴逆飞布；兼容门本位地盘干法。
- 寄宫与暗干口径必须随结果持久化并在结果页可见。

### R4 可审计本地分析

- 分析采用“事实层 → 裁决层 → 应期层”，运行时派生、不落库。
- 事实层覆盖九星八门旺衰、门迫、六仪击刑、奇仪入墓、空亡、驿马、伏吟反吟、五不遇时、十干克应、三奇吉格、九遁及锁定规则表中的常见凶格。
- 裁决层结合问事类型、日干/时干、值符值使、用神宫和事实标签，输出“可成、难成、待条件、趋势不明”、证据链与应期候选。
- 禁止百分制、星级或加权吉凶评分；每条规则必须带来源、理由与关联宫位。

### R5 产品界面与应用接入

- 首页提供启用的奇门入口；起局页完整承载时间、定局法、校盘口径、占问类型与高级参数。
- 结果页提供稳定 3x3 洛书九宫盘、单宫详情、盘局摘要、规则分析、裁决、应期与 AI 区域。
- 小屏、大字体和动态标签不得造成文字重叠或九宫尺寸跳动。
- 接入统一 UI factory、Provider/ViewModel、历史卡片与详情重开流程。

### R6 持久化与数据管理

- 使用稳定系统 ID `qimen` 和现有 `time` / `manual` method ID。
- `QimenResult.toJson()` / `fromJson()` 必须完整可逆；历史重开与首次结果一致。
- 接入按系统统计、导入导出、清理和最近记录；无需新增数据库表或 schema migration。

### R7 AI 结构化输出

- 提供并注册 Qimen formatter、系统/综合/简要模板和问事引导。
- AI 输入包含排盘口径、完整九宫、规则事实、裁决和应期，并明确禁止 AI 自行重排或静默替换程序结论。
- 未配置 AI 时，本地盘面和分析仍完整可用。

### R8 文档与质量

- 新增系统级契约 `docs/architecture/divination-systems/qimen.md` 及 Trellis domain specs。
- 核心规则必须有来源化黄金盘和阶段单测；跨层流程必须有仓储与 widget 测试。
- 代码生成、静态分析、目标测试和全量测试全部通过，现有术数行为无回归。

## Task Map

| 子任务 | 交付 | 顺序依赖 |
|---|---|---|
| `07-28-qimen-pan-engine` | 时间归一化、三种定局法、完整转盘九宫、模型/系统、序列化、黄金盘 | 首先实施 |
| `07-28-qimen-analysis-engine` | 事实标签、规则表、保守裁决、应期与 analyzer | 依赖排盘子任务的冻结模型与黄金盘 |
| `07-28-qimen-product-integration` | 起局/结果 UI、九宫交互、注册、历史、数据管理、AI、资源与端到端测试 | 依赖前两个子任务 |

父任务不直接承载产品代码；三个子任务完成后由父任务执行跨子任务集成复核。

## Acceptance Criteria

- [ ] 三个子任务按顺序通过各自质量门并归档。
- [ ] 用户可从首页完成自动或手动起局、保存、查看结果、进入单宫详情、查看本地分析/应期与发起 AI 解读。
- [ ] 三种定局法、三种时间基准、两种换日规则、两种寄宫和两种暗干口径均可复算并有边界测试。
- [ ] 结果 JSON 与仓储往返保持完整深比较；历史详情和首次结果盘面一致。
- [ ] 每条本地分析结论可追溯到结构化事实和来源，不出现数值吉凶评分。
- [ ] 奇门记录可被历史筛选、数据管理统计、导出、导入和按系统清理。
- [ ] AI formatter 与模板可用；无 AI 配置时 UI 正常降级。
- [ ] `flutter analyze`、目标测试和全量 `flutter test` 通过，现有术数零回归。

## Out of Scope

- 飞盘奇门、阴盘奇门。
- 年家、月家、日家奇门。
- 自动定位、地图选点或后台位置权限；真太阳时经度由用户手动输入。
- 云同步或数据库 schema 重构。
- 未在 R4 规则表中锁定的全古籍断语库。

## Constraints

- 规则分歧必须以稳定参数显式表达，不能藏在 UI 或环境默认值中。
- 排盘事实完整持久化；分析报告运行时派生。
- 系统、UI、历史和 AI 未全部接通前不得以启用状态进入发布入口。
- 外部开源实现仅用于交叉校验；移植代码必须满足许可证归属要求。
