# 六爻古籍分析体系与 AI 提示词优化

## Goal

在不推翻现有排盘与四值裁决的前提下，把六爻分析升级为一条可执行、可追溯、可评测的完整链路：盘面事实 -> 用神角色 -> 日月与状态 -> 动变和有向作用 -> 冲突裁决 -> 未决条件 -> 应期观察窗 -> 古籍/项目证据 -> AI 解释。最终 AI 必须忠实解释程序结果，只引用输入中已经核验的来源，并通过真实模型的古例对照证明相较当前提示词没有事实回归且解释质量有所改善。

## Background

- 当前 `LiuYaoAnalyzer` 已实现日月旺衰、空亡、墓绝、合冲刑害、动变、生克、飞伏、卦变、用神链、四值裁决和应期；分析为运行时派生数据，只有用户选定的用神位置/伏神标志持久化。
- 裁决基准已由历史决策锁定：以《增删卜易》为主干；《卜筮正宗》只补充三刑、六害等低优先级规则，不做流派切换。
- 现有黄金矩阵为 40 例，其中 26 个标为原书占例、14 个标为章法校验例；案例有章节和校对本印刷页定位，但缺稳定规则/来源 ID、短引类型、版本和独立元数据校验。
- `YaoAnalysisTag` 的中文 `term` 同时充当展示文本和运行时规则身份；裁决与应期按字符串消费，术语改名可能改变行为。
- 连续相生/相克当前丢失有向关系，元神与忌神的受制判断不对称；应期先于裁决计算，无法只从可解的未决条件生成观察窗。
- AI formatter 已经拿到完整 `AnalysisReport.judgment`，却只输出爻标签、用神位置、简写应期和一行摘要，丢弃完整条件、因素、来源和伏神自身事实。
- 本地《增删卜易（校对：中国男儿）》PDF 已固定 SHA-256 并完成四组关键页的文本/渲染复核；本地《卜筮正宗》PDF 因字体映射问题尚不能作为页级直接证据。
- `devtools_options.yaml` 是 Git 已跟踪的 Flutter DevTools 三字段配置文件，当前没有 API 地址、key 或模型字段。真实模型评测需要独立、被 Git 忽略的本地配置或环境变量。

## Requirements

### R1 固定分析体系

- 保留 `LiuYaoAnalyzer` 作为唯一领域入口，明确并文档化固定阶段：输入/盘面、用户用神、角色清单、基础状态、动变状态、有向作用、辅助证据、冲突裁决、四值结论、未决条件、应期、AI 投影。
- 用户已选用神时，它是最高优先级事实，AI 和程序均不得重选；未选用神时只允许输出“候选建议”，不得伪造程序裁决或应期。
- 六神、神煞、卦义和世应象意保持辅助层，不能静默推翻用神中心的程序裁决。

### R2 古籍与项目证据合同

- 建立六爻专属的版本化 source/rule catalog，至少记录稳定 ID、资料类型、题名/版本、固定 revision 或文件指纹、定位、短引/转述类型、证据等级、采用状态、适用边界和项目裁定。
- 每个可由 analyzer 产出的主规则 term、裁决行和应期规则必须能解析到稳定 rule ID 与 source ID；别名只映射到主规则，不重复参与裁决。
- 直接引文必须经过页级复核；无可靠页级证据时只可标为 `paraphrase`、`projectConvention` 或 `locatorOnly`，不得伪装为原文。
- 四值、强弱三分类、首行命中和软件冲突顺序必须归为项目约定；组成这些判断的古籍谓词另行引用，不能统一冒充“《增删卜易》断法总论”。
- 三刑、六害在《卜筮正宗》证据未完成页级复核前继续保持低优先级、非决定性。

### R3 稳定规则身份与有向事实

- 中文展示词与执行身份解耦；裁决和应期优先消费稳定 rule ID，并在迁移期保留现有 term 和现有 UI 文案。
- 表达有向生克/扶助链的 `from`、`to`、路径顺序、是否生效及受何规则压制；只有实际指向用神的作用才能改变用神受力。
- 元神和忌神使用同一套 actor availability 判定，覆盖回头克、化退、冲散、日/月合绊等受制状态。
- 修正“伏神已得出仍保留待出伏”等已确认的因果矛盾；所有语义修正必须先依据古籍/项目裁定更新黄金期望，再调整引擎，禁止为通过测试写个案特判。

### R4 裁决与应期链路

- 裁决因素、命中决策行、条件和应期均具有稳定 ID 及来源链接；因素顺序体现裁决层级而非 UI priority。
- 先形成四值裁决与完整条件集，再由仍未解除且 `hasRescue=true` 的条件生成应期观察窗；不可解条件不得生成暗示成功的通用应期。
- 同一时间候选解除多个条件时保留全部上游条件/规则引用；现有日/月尺度及日历匹配行为保持兼容。

### R5 AI 结构化投影与提示词

- 新增版本化 Liuyao AI projection，完整提供用神模式、用神/元神/忌神/仇神、用神自身事实、有向作用、四值趋势、nuance、全部条件、全部因素、应期尺度/原因/上游条件、命中来源及计算所有权策略。
- 最终 system guard 不依赖可替换的自定义模板，至少固定 `calculationOwner=program`、禁止重排/重算、禁止覆盖程序裁决、禁止伪造古籍原文/页码、只可解释提供的来源和应期。
- 更新六爻 comprehensive 与 brief 内置模板，保持现有模板 ID；修复真实装配中的 `hasChangingGua` 等上下文缺口。
- 输出顺序固定为：问题与取用边界 -> 盘面/世应 -> 日月与状态 -> 动变/作用链 -> 裁决与反证 -> 未决条件 -> 应期 -> 古籍依据 -> 有边界的建议。
- 既有对话继续使用冻结旧提示词；用户重新生成/新建对话时使用新规则与提示词，并可看到分析/提示词版本。

### R6 用户可见古籍参考

- 术语词典弹窗展示该主规则的来源类型、书名/项目约定、章节/印刷页或 locator、采用释义和证据边界。
- UI 不展示本机绝对路径，不把 `locatorOnly` 文本渲染成逐字引文；现有结果页布局不做重设计。

### R7 真实模型评测与凭据安全

- 增加显式 opt-in 的六爻提示词评测工具和版本化 rubric，复用黄金案例的单一事实源；案例性质用 `caseKind=originalBook|ruleValidation`，调优用途用 `evaluationSplit=calibration|holdout`，两者必须正交且 holdout 仅允许原书例。
- 基线与候选使用相同模型、参数、结构化输入和请求顺序控制；记录非敏感模型元数据、提示词/fixture hash、延迟、token 和评分，不记录 key/header/完整异常对象。
- 硬门禁包括：程序四值不被改写、条件不遗漏、用神和盘面不捏造、应期不承诺必然发生、引用只来自输入 source registry、无伪造原文或页码。
- 候选在所有硬门禁上不得低于基线；冻结 rubric 的七个维度均按 `dimension x cohort` 独立判定，不允许用总分抵消单项回归；综合证据覆盖、冲突解释、来源忠实、条件/应期解释和问题贴合度中至少一项达到预注册的可重复改善阈值。
- 每次评测显式绑定唯一 `runId`；生成、盲审、比较和扫描必须拒绝 fixture、rubric、projection、模型、请求参数或 run hash 不一致的产物。holdout 只允许首次冻结候选揭示一次，揭示后只能标为回归集，不能再次用于 AC9 调优结论。
- 凭据只从环境变量或专用 gitignored 本地配置读取；评测产物写入前后均执行敏感值和 Authorization 模式扫描。

### R8 兼容、测试与文档

- 不改变现有排盘 JSON 和数据库 schema；分析继续运行时派生，不把 rule report 持久化到历史记录。
- 所有新模型字段采用兼容扩展；其他术数系统共享裁决模型的现有行为保持不变。
- 增加 catalog 完整性、规则正反例、有向作用、actor availability、条件到应期、formatter projection、真实 Liuyao PromptAssembler、custom template guard、旧 conversation snapshot 和 glossary 来源展示测试。
- 更新 `.trellis/spec/domain/liuyao-analysis-engine.md` 与 `docs/architecture/divination-systems/liuyao.md`，使规则版本、证据等级、阶段顺序、AI 边界和评测口径与代码一致。

## Product Decisions

- 继续采用《增删卜易》主干 + 《卜筮正宗》低优先级补充，不增加流派切换或为了数量扩充古籍清单。
- 保留用户自由点选用神；本期不新增自动分类并持久化用神。未选时的 AI 候选只作明确标注的建议。
- “靠拢实际结果”以已知原书占例的结论一致性、证据链忠实度和非臆造程度为可复现代理指标，不宣称单次输出证明现实预测准确率。

## Acceptance Criteria

- [x] AC1：文档和运行时 projection 均呈现同一条固定分析阶段链，并带 `analysisSchemaVersion`、`ruleSetId`、`ruleSetVersion` 和计算所有权策略。
- [x] AC2：catalog validator 证明所有 analyzer 主规则、决策行和应期规则都有唯一稳定 ID、已知来源和合法证据状态；决定性项目规则不冒充古籍原文。
- [x] AC3：至少对《增删卜易》高影响规则族完成页级证据与短引复核；《卜筮正宗》未复核项只能保持 locator-only/非决定性。
- [x] AC4：有向连续相生/相克、受制元神/忌神、月合绊和伏神得出均有正反例；裁决只消费实际指向用神且仍生效的作用。
- [x] AC5：应期只由可解未决条件产生，并保留全部上游条件/规则链接；现有日历的日/月尺度回归通过。
- [x] AC6：真实六爻 formatter/prompt 端到端 fixture 含完整用神事实、趋势、全部条件/因素、应期、来源和 guard；未选用神 fixture 不产生伪程序裁决。
- [x] AC7：comprehensive、brief 和 active custom template 三条路径都不能移除程序所有权、禁止覆盖、禁止伪引和应期边界；既有冻结会话保持旧快照。
- [x] AC8：术语词典能显示来源与证据边界，且不暴露绝对路径或把转述显示为逐字原文。

## Out Of Scope

- 自动问事分类、自动持久化用神、用神 UI 流程重设计。
- 把六神、神煞、卦名象意或外应提升为决定性裁决规则。
- 新增流派切换、整库古籍数字化、提交本地 PDF/DOCX/DOC 原件。
- 修改其他术数系统的规则语义、数据库迁移或历史排盘重写。
- 用模型输出作现实预测准确率或事件必然性的统计声明。
